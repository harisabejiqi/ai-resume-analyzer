# Archived runs — the label-quality comparison

These two runs exist to support one finding: **tightening the grade-1 definition
changed the conclusions more than any algorithmic change tested.**

Both were produced from the *same* 25 resumes and 9 job descriptions, with the
*same* code and the same seed. The only difference is `labels.csv`.

| | `labels_loose/` | `labels_strict/` |
|---|---|---|
| grade-1 rule | "adjacent field with real overlap" | "adjacent profile with substantial transferable evidence, missing an important requirement" |
| pairs | 225 | 225 |
| grade distribution | 162 / 42 / 21 | 181 / 24 / 20 |

24 of the 225 labels changed (11%): 19 demotions from 1 to 0 where the only
overlap was shared vocabulary, 3 demotions from 2 to 1 for a missed stated
requirement, 2 promotions from 1 to 2 for candidates who were in fact qualified.

## What reversed

| comparison | loose labels | strict labels |
|---|---|---|
| `sbert_chunk` vs `sbert` (does chunking help?) | ΔNDCG +0.048, **p = 0.959** | ΔNDCG +0.048, **p = 0.043** * |
| `tfidf_corpus` vs `tfidf` (does corpus IDF help?) | **p = 0.018** * | **p = 0.500** |

Read on the loose labels, the harness said chunking was worthless and that the
shipped TF-IDF needed replacing with a precomputed IDF vocabulary. Both
conclusions were artefacts of grade-1 rewarding shared vocabulary. Acting on them
would have meant discarding a method that works and building a component that
isn't needed.

## Why these are archived rather than deleted

They are the evidence for the finding above. Everything else is reproducible from
the current `data/labels.csv`, so the live numbers live in `eval/results/` and
are regenerated by `python -m eval.run_eval`.

Note that neither run reflects the current gold set: both predate the two sparse
resumes (`sparse_backend_01`, `sparse_nurse_01`) added to expose the short-CV
scoring effect. Cite them **only** for the label comparison, never as current
results.
